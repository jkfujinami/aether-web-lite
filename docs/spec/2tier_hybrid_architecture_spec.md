# AETHER Lite 2層ハイブリッドアーキテクチャ設計仕様書
*(2-Tier Hybrid Architecture: Control/Conversation Plane & Bulk Storage Plane)*

## 1. 設計背景と解決すべき根本課題

### 1.1 現行アーキテクチャのボトルネック
10ノード仮想ネットワークによる実測プロファイリングで判明した遅延要因:
1. **二重オニオン送出**: 本体（DHT）と索引（Hint）の2回に分けたオニオン回路送出により、最短でも約6.8秒（Cover待機1秒 + Exit遅延2.2秒 × 2回）を消費。
2. **過剰な時間分離タイマー**: `HintReleaseScheduler` がトラフィック観測時に最大60秒の意図的スリープを挿入。
3. **エコータイムアウト**: 回路構築失敗時に `ZoneGossipRouter` が45秒間UIをブロック。
4. **WebRTCとDHTの不整合**: 直結隣人（8〜12台）しか知らないブラウザ環境で、遠隔ノードを前提とするDHT_GETを実行した結果、平文クエリ漏洩とタイムアウトが発生。

### 1.2 コア設計思想: 「会話」と「大容量データ」の直交分離
BitTorrent、IPFS、本家 AETHER Core が示す通り、全網ゴシップ（プッシュ型配信）と分散ストレージ（プル型配信）を同一のパイプラインで処理することはできません。
本仕様では、通信を以下の2層に完全分離します。

```text
┌────────────────────────────────────────────────────────────────────────┐
│                        AETHER 2層アーキテクチャ                        │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│  【Layer 1: 会話・制御プレーン】 (Control & Conversation Plane)        │
│   ・対象: テキスト投稿、返信、スレッドメタデータ、ファイル共有マニフェスト │
│   ・規格: 固定 4,096 バイト (サイズ指紋排除)                           │
│   ・経路: 単一オニオン回路 (Guard → Exit) → 全網 Fluff (Broadcast Veil)│
│   ・遅延: E2E 約 0.8秒 〜 1.2秒 (即時反映)                             │
│   ・性質: DHT不使用。誰も「この投稿をくれ」と要求しない (受信者完全匿名)  │
│                                                                        │
├────────────────────────────────────────────────────────────────────────┤
│                                                                        │
│  【Layer 2: バルクストレージプレーン】 (Bulk Data Plane)               │
│   ・対象: 画像、音声、数GB級の巨大ファイル                             │
│   ・規格: 固定 262,144 バイト (256KB チャンク)                         │
│   ・経路: Merkle Tree / Swarm 並列PULL / Reed-Solomon 消失訂正         │
│   ・担い手: 常時起動の Desktop ノード群 (Seeder / Holder)              │
│   ・性質: 欲しいノードだけがマニフェストをもとに並列取得               │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

## 2. Layer 1: 会話・制御プレーン仕様 (即時掲示板)

### 2.1 パケット規格: 4KB 固定長フレーム
パケットサイズによるトラフィック解析（長文/短文、誰の投稿かの推測）を完全に排除するため、Layer 1 の全パケットを **4,096 バイト固定長** に統一します。

```text
┌───────────────┬──────────────────────────────────┬─────────────────┬──────────┐
│ Magic & Ver   │ 暗号化ペイロード (ChaCha20-Poly1305) │ パディング (乱数)│ PoW 証跡 │
│ (4 bytes)     │ (可変長: 本文、DAG、署名)        │ (4096Bに正規化) │ (8 bytes)│
└───────────────┴──────────────────────────────────┴─────────────────┴──────────┘
```

```typescript
export const L1_PACKET_SIZE = 4096; // 4KB 固定長

export interface L1ConversationPacket {
  version: 1;
  board_id: string;
  thread_id: string;
  packet_id: string;
  timestamp: number;        // 分単位丸め
  parents: string[];        // Merkle-DAG 親パケットID (Tips)
  cumulative_pow: number;
  content: {
    type: 'text' | 'manifest_ref';
    body: string;           // テキスト本文、またはファイル共有マニフェストJSON
  };
  signature: Uint8Array;    // 作成者署名 (Ed25519)
}
```

### 2.2 送信・中継シーケンス (単一オニオン)
本体とHintの二重送出を撤廃し、**1回のオニオン回路送出で完結**させます。

```text
[送信クライアント]
  1. メッセージ作成 & 4KB 固定長へ暗号化・パディング
  2. 単一オニオン回路 (Guard → Exit) へ投入
     - Cover Traffic 待ち (推奨: 200〜400ms)
     - Guard 中継
     - Exit 混合遅延 (推奨: 400〜600ms)
     ── [合計所要: 約 0.8秒] ──>
[Exit ノード]
  3. 最内層を解き、平文の 4KB 暗号化パケットを取り出す
  4. 全隣人へ GOSSIP (Fluff) としてフラッディング放出
     ── [伝播所要: 数ミリ秒〜数十ミリ秒] ──>
[全網の全ピア (Broadcast Veil)]
  5. 手持ちの板鍵/スレッド鍵で試行復号
     - 復号成功: その場で DAG に追加し、UI へ即時反映 (取得遅延: 0ms)
     - 復号失敗: 中身不明のパケットとして隣人へ中継・保持
```

### 2.3 受信者匿名の完全保証
従来の `DHT_GET`（平文クエリ）を完全撤廃します。全ノードが全 4KB パケットを無条件に受信するため、**「誰がその投稿を読んだか」は物理的に外部から観測不能**になります。

## 3. Layer 2: バルクストレージプレーン仕様 (数GB共有基盤)

### 3.1 チャンク規格: 256KB 固定ブロック
巨大ファイルを安全かつ効率的に転送するため、本家 AETHER Core の規格に合わせ **256KB（262,144 バイト）** を基本単位とします。

- **チャンキング**: ファイルを 256KB 単位に分割。
- **暗号化**: 収束的暗号化（Convergent Encryption）または スレッド固有鍵による ChaCha20-Poly1305。
- **アドレス指定**: `content_address = SHA256(chunk_ciphertext)`（内容アドレス指定）。

### 3.2 マニフェスト参照モデル
ファイル本体は会話ストリーム（Layer 1）には一切流しません。
ファイル共有時は、Layer 1 の投稿内に **マニフェスト参照（`manifest_ref`）** を埋め込みます。

```json
{
  "type": "manifest_ref",
  "name": "large_archive.tar.gz",
  "size": 4294967296,
  "chunk_size": 262144,
  "root_hash": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855",
  "chunks": [
    "chunk_hash_0001",
    "chunk_hash_0002"
  ],
  "encryption_key": "..."
}
```

### 3.3 取得モデル (Swarm PULL)
1. 掲示板には「ファイル名、サイズ、ダウンロードボタン」が 1 秒で即時表示される。
2. ユーザーがダウンロードを要求した時のみ、Layer 2 のストレージノード群（常時起動の Desktop ノードやシーダー）に対して 256KB チャンクを並列要求。
3. ブラウザ版（WebLite）は Origin Private File System (OPFS) または ServiceWorker Cache へ逐次書き込み、メモリ枯渇を防止。

## 4. 移行・リファクタリング計画

| コンポーネント | 現行の動作 | 改訂後の動作 |
| :--- | :--- | :--- |
| **`SchrodingerMailbox`** | 本体とHintを分離し、二重オニオン送出 | **会話パケットの単一オニオン直接送出へバイパス** |
| **`DHTMailbox`** | 平文 `DHT_GET` による同期待ち | **会話時の同期 GET を完全廃止** (ローカルDAG直結) |
| **`OnionCircuit`** | `EXIT_DELAY_MS = 2500` / `COVER = 2000` | **`EXIT_DELAY_MS = 500` / `COVER = 300`** へ高速化 |
| **`ZoneGossipRouter`** | Hintエコー待ち、45秒タイムアウト | **パケット受信時の即時DAG追加 & タイムアウト 5秒** |
| **`PacketBuilder`** | 可変長 JSON パケット生成 | **4KB 固定長パディングフレーム生成** |
